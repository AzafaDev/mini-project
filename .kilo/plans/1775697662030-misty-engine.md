# Comprehensive Auth Endpoints Test Plan
All endpoints base path: `/api/auth` (standard convention for this project)

---

## 1. POST /register
**Description**: Register new user account

### Test Scenarios:
✅ Valid registration with complete valid data
❌ Missing required fields (email, password, name)
❌ Invalid email format
❌ Password too short (< 8 chars)
❌ Email already exists in system
❌ Password lacks complexity requirements

### Curl Command:
```bash
curl -X POST http://localhost:3000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "SecurePass123!",
    "name": "Test User",
    "phone": "+1234567890"
  }'
```

### Expected Response:
✅ **201 Created**:
```json
{
  "success": true,
  "data": {
    "user": { "id": "uuid", "email": "test@example.com", "name": "Test User", "emailVerified": false },
    "tempToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  },
  "message": "Registration successful. Please verify your email."
}
```
❌ **400 Bad Request**: Validation errors
❌ **409 Conflict**: Email already registered

## 2. POST /verify-email
**Description**: Verify user email address with OTP token

### Test Scenarios:
✅ Valid email + correct verification code
❌ Invalid verification code
❌ Expired verification code
❌ Already verified email
❌ Non-existent email

### Curl Command:
```bash
curl -X POST http://localhost:3000/api/auth/verify-email \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "code": "123456"
  }'
```

### Expected Response:
✅ **200 OK**:
```json
{
  "success": true,
  "message": "Email verified successfully",
  "data": { "accessToken": "...", "refreshToken": "..." }
}
```
❌ **400**: Invalid/expired code
❌ **404**: User not found

## 3. POST /resend-verification
**Description**: Resend email verification code (requires valid temp token)

### Test Scenarios:
✅ Valid temp token from recent registration
❌ Invalid/expired temp token
❌ Already verified user
❌ Missing temp token header

### Curl Command:
```bash
curl -X POST http://localhost:3000/api/auth/resend-verification \
  -H "Authorization: Bearer <TEMP_TOKEN_FROM_REGISTER>"
```

### Expected Response:
✅ **200 OK**: `{"success": true, "message": "Verification email resent"}`
❌ **401 Unauthorized**: Invalid temp token

## 8. PUT /change-password
**Description**: Change password for authenticated user

### Test Scenarios:
✅ Correct current password + valid new password
❌ Wrong current password
❌ New password same as old password
❌ New password fails complexity rules
❌ Unauthenticated request

### Curl Command:
```bash
curl -X PUT http://localhost:3000/api/auth/change-password \
  -H "Authorization: Bearer <ACCESS_TOKEN>" \
  -H "Content-Type: application/json" \
```

### Expected Response:
✅ **200 OK**: `{"success": true, "message": "Password changed successfully"}`

### Test Scenarios:
✅ Valid existing email returns success
❌ Non-existent email (should still return 200 for security)
❌ Invalid email format
❌ Rate limit exceeded

### Curl Command:
```bash
curl -X POST http://localhost:3000/api/auth/forgot-password \

  -d '{

  }'
```

### Expected Response:
✅ **200 OK**: `{"success": true, "message": "If this email exists, reset link has been sent"}`

## 10. POST /reset-password/:token
**Description**: Complete password reset with valid reset token

### Test Scenarios:
✅ Valid reset token + valid new password
❌ Invalid/expired reset token
❌ Password does not meet complexity requirements
❌ Token already used once

### Curl Command:
```bash
curl -X POST http://localhost:3000/api/auth/reset-password/abc123xyz789 \
  -H "Content-Type: application/json" \
  -d '{
    "password": "NewSecurePass789!"
  }'
```

### Expected Response:
✅ **200 OK**: `{"success": true, "message": "Password reset successfully. You can now login."}`
❌ **400**: Invalid/expired token or password violation
❌ **410 Gone**: Token already consumed

---

## General Test Notes:
- All endpoints return standard `{ success: boolean, data?: object, message?: string, errors?: [] }` format
- Rate limiter: 10 requests / minute for auth sensitive endpoints
- All POST/PUT endpoints require `Content-Type: application/json` header
- Token expiry: Access token 15min, Refresh token 7 days, Temp token 1 hour, Reset token 15min
- All error responses include consistent error codes and human readable messages
